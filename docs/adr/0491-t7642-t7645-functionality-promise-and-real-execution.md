## 一、 背景与动因

在对插件暴露给用户的全部一级、二级与三级入口进行六段式闭环排查（输入、处理、持久化、重载后仍在、可撤销、异常可恢复）过程中，发现了以下两处违背功能真实承诺的隐蔽缺陷：
1. **剪贴板写入异步错误被吞与假成功提示**：`copyToClipboard` 与 `exportTabsAsMindmap` 此前使用 `void navigator.clipboard.writeText(...)` 发出后立即弹出“已复制到剪贴板”消息。在系统未授权剪贴板、窗口失去焦点或浏览器安全限制时，Promise 被静默拒绝，但用户依然看到成功提示，造成“假成功”体验；
2. **生态插件未安装时的虚假回执**：在次级动作画板中执行“在思阅中打开”或“在思播中打开”时，若用户未安装配套生态插件，代码回退为在普通原生编辑器打开，却依然向用户展示“已在思阅/思播中打开”的虚假回执，导致用户产生信任断裂。

---

## 二、 架构决策与标准落地

### 1. T-7642 剪贴板真实 Promise 捕获与如实反馈
- `src/index.ts` 与 `src/index.js` 中的 `copyToClipboard` 与 `exportTabsAsMindmap` 统一改为等待 `writeText` Promise：
  - 成功时展示成功提示；
  - 捕获异常（`.catch`）时如实报警提示“复制失败，请检查剪贴板权限”；
  - 环境不支持剪贴板时明确提示不可用，杜绝发出未等待的虚假成功。

### 2. T-7643 生态插件动作活跃态真实检测与消伪回执
- `open-in-reader` 与 `open-in-media` 严格检测 `isReaderActive` 与 `isMediaActive`：
  - 插件真实就绪且调用成功时才展示“已在思阅/思播中打开”；
  - 未安装配套插件时，在打开原生页签的同时如实提示“未检测到思阅/思播插件，已在默认编辑器中打开”，绝不掩盖真实行为。

### 3. T-7644 全入口可用性矩阵与真实测试
- 针对全平台暴露的 38 个一级至三级入口完成六段式状态核查（详见工作底稿）；
- 新增专项测试 `tests/functionality-promise-and-real-execution-contract.test.cjs`。

### 4. T-7645 门禁验证与交付
- 跑通全部 8 套样式门禁与功能契约测试，保持离线自律闭环。
