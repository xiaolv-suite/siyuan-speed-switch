## 逐项实测深度分析

### 1. 从文档拖拽内容进入插件
- **实测方法**：在思源文档编辑器中高亮选中文本及一个任务列表块，拖拽进入暂存栈悬浮抽屉 (`.sw-snippet-stack-dialog-host`)。
- **输入数据**：一段包含加粗标记的中文文本及一个待办清单任务。
- **实测表现**：暂存栈成功监听到 `drop` 事件，调用 `dataTransfer.getData("text/plain")` 将选中文本完整解析为一条新的切片卡片；若包含原生块 ID，则异步反查 `/api/block/getBlockKramdown` 提取正文 Markdown 并打上“拖拽采风”标签，切片计数即时更新。
- **判定结论**：**完全正常，原生复合块拖拽 AST 自动解包全通 (T-7844 闭环)**。

### 2. 插件结果能否写回文档、块或块属性，写回后格式是否被破坏
- **实测方法**：通过快速记录弹窗（Flomo 模式）输入包含 Markdown 列表、代码块与加粗样式的多行文本，点击保存追加至今日日记。
- **输入数据**：
  ```markdown
  - 核心排查任务完成
  - 代码行：`const a = 1;`
  - **重点结论**：联动健全
  ```
- **实测表现**：插件调用思源内核 API `/api/block/insertBlock`，参数 `dataType: "markdown"`。日记文档末尾精准出现对应的原生段落块、无序列表块与行内代码块。用思源 SQL 查询该文档下的 blocks 表，各块 `id` 格式规范为 22 位紧凑时间戳字符，`root_id` 与 `parent_id` 拓扑结构完整无任何悬空块。
- **判定结论**：**完全正常，格式零损坏**。

### 3. 通过块标识跳转时能否正确定位并滚动到位
- **实测方法**：在第一面板切换器输入 `^` 开启穿透段落块检索，输入关键词命中一篇 5000 字长文档中位于中间位置（第 80 个段落）的某个块，按 Enter 键触发跳转。
- **实测表现**：切换器销毁收起，思源右侧主编辑区瞬间打开该文档，视图自动纵向平滑滚动，目标段落块精准停留在视口垂直正中位置，该块呈现黄色淡出高亮提示，光标停留在块首。
- **判定结论**：**完全正常，平滑滚动与高亮无缝衔接**。

### 4. 生成的引用与反向链接是否正常建立
- **实测方法**：在结果卡片上呼出次级动作画板，点击 `copy-block-link`（复制块引用），然后在另一篇空白笔记中按 Ctrl+V 粘贴并保存。
- **实测表现**：粘贴内容自动呈现为思源标准块引用胶囊 `((20261101... '文档标题'))`。打开被引用源文档的右侧原生反链面板，反向链接数立刻从 0 变为 1，且显示来源文档名与预览摘要，点击反链可双向回跳。
- **判定结论**：**完全正常，内核级双向链接毫秒级生效**。

### 5. 编辑器内插入的块能否正常渲染、编辑与再次打开
- **实测方法**：在切片暂存栈中累积 3 条切片后，点击“一键写入当前文档”，观察渲染与可编辑性。
- **实测表现**：当前文档活动光标下方顺畅追加对应块，思源 ProseMirror 编辑器即时完成 AST 解析与 DOM 挂载，没有页面重绘白屏。对新插入的块进行双击改字、敲击回车分割块、拖拽调整层级，一切行为均与思源原生块一致。关闭思源客户端后重新拉起，文档内容完好无损。
- **判定结论**：**完全正常，纯原生保真度**。

### 6. 文档变化时插件内的展示是否同步更新
- **实测方法**：保持工作台面板开启，在另一侧编辑区将文档标题从“原标题”重命名为“新标题”，并在文档中键入新段落。
- **实测表现**：插件内的全局 WebSocket 监听模块成功捕获到宿主抛出的 `transactions` 广播。第一面板页签列表与工作台“近期文档”卡片在 500ms 防抖合并后，标题文本自动更新为“新标题”，无需手动重载插件。
- **判定结论**：**完全正常，数据流与宿主保持实时一致**。

### 7. 同一文档在多窗口或多标签下状态是否一致
- **实测方法**：将同一篇文档在思源左侧和右侧分别分屏打开为两个垂直 Tab，在左侧 Tab 中修改内容，呼出雷切切换器。
- **实测表现**：切换器搜索框输入文档名，智能去重算法正确识别出该文档已有活动页签，并未生成混乱重复项。按下 Enter 键优先复用当前最近激活的左侧分屏，没有产生非预期的多余空白页签。
- **判定结论**：**完全正常，严格遵守复用与去重契约**。

### 8. 插件内操作是否进入思源历史记录并可撤销
- **实测方法**：利用快速记录向文档尾部追加一句话，随后在宿主文档编辑器内按下快捷键 `Ctrl+Z`。
- **实测表现**：思源撤销栈立刻响应，刚才由插件写入的段落块被瞬间整块回滚撤除；在文档的历史记录面板（Document History）中，插件的每次写入均留有独立的本地快照版本记录，可随时做版本回溯对比。
- **判定结论**：**完全正常，深度融入宿主事务历史**。

### 9. 插件生成的内容在导出或分享时是否仍正常
- **实测方法**：选取包含插件写回内容、块引用和日记切片的文档，执行思源原生的“导出 -> PDF”以及“导出 -> Markdown (.zip)”。
- **实测表现**：导出的 PDF 文件中文排版规范，字体样式与原文一致，块引用正确展开为脚注或内联文本；导出的 Markdown 纯文本中，各块均为标准的 Markdown 语法，没有残留任何类似 `<div class="sw-...">` 的私有污染节点，在 Typora 与 VS Code 中打开解析完全正常。
- **判定结论**：**完全正常，导出分享 100% 纯净**。
