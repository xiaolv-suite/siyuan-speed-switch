# 小驴雷切候选功能清单 (Candidate Backlog)

> **原则**：存量优化阶段严禁擅自增加新功能！所有排查与走查过程中发现的“可以做得更好或缺少让体验更完整的点”，必须单独记入本清单，保持与修复待办池彻底分离。
> 每一条必须包含：**是什么**、**解决什么问题**、**影响哪类用户**、**预估成本**、**与现有功能是否重叠**。
> 由用户审查决策后，决定加的转入待办池，不加的标注原因留存，杜绝反复讨论。

## 候选功能列表

### `CAND-01`：从思源大纲树/块标直接拖拽原生块对象时的 AST 自动解包支持
- **是什么**：在切片暂存栈（`src/snippet-stack-ui.js`）的拖拽监听中，增加对思源原生拖拽数据（MIME `siyuan/block`）的深度解析：检测到块 ID 时，异步调用 `/api/block/getBlockKramdown` 自动抓取正文 Markdown，而非仅存入空 ID 链接文本。
- **解决什么问题**：消除拖拽原生复合块时仅能捕获到链接文本、需手动二次进入复制正文的体验断点，让拖拽摘录真正开箱可用。
- **影响哪类用户**：习惯通过鼠标从文档大纲树或正文块把手中快速拖拽段落做知识卡片切片整理的重度用户。
- **预估成本**：**小（1）**（局部在 drop handler 中增加块 ID 提取与异步内容填充）。
- **与现有功能是否重叠**：否。现有逻辑仅捕获标准 `text/plain` 纯文本，未接入思源原生块 AST 反查链路。
- **用户审查决策状态**：`已批准转入待办池执行 (T-7844)`

### `CAND-02`：切换器结果卡片右键菜单增加“置顶此文档”快捷项
- **是什么**：在第一面板卡片右键菜单（`swCardMenu`）中追加“固定/取消固定此页签 (`toggle-pin`)”菜单项。
- **解决什么问题**：目前固定页签只能通过卡片悬停把手上的小图钉按钮触发，对于习惯全局右键菜单操作的用户存在交互死角，补齐右键入口可统一操作心智。
- **影响哪类用户**：多任务切换频繁、重度依赖右键菜单管理页签的高级用户。
- **预估成本**：**极小（0.5）**（在 `src/doc-search-ui.ts` 的右键菜单列表追加一行已有的 `togglePin` 调用）。
- **与现有功能是否重叠**：轻微重叠（悬停把手已有），但属于交互入口的正交补齐，不增加系统复杂度。
- **用户审查决策状态**：`已核实被现有实现覆盖 (Closed · src/index.ts:13818 确已实现)`

### `CAND-03`：悬浮球更多动作抽屉支持字母拼音快速单键跳转

- **影响哪类用户**：全键盘无鼠标流用户及移动端外接键盘打字用户。
- **预估成本**：**小（1）**（在抽屉 keydown 监听中增加非输入态下的首字母匹配光标移动）。
- **与现有功能是否重叠**：否。现有快捷键仅覆盖 `1~9` 数字键槽位。

- **与现有功能是否重叠**：否。现有 Tab 键在结果卡片聚焦时是呼出次级动作画板，搜索框内的 Tab 键尚未被赋权。

### `CAND-14`：工作台小组件「内容自适应最小高度 + 瀑布流布局」模式
- **是什么**：在现有 12 列网格之上增加一个可选布局模式：卡片高度不再由固定 40px 行单元 × 行跨度决定，而是按内容实际高度自适应撑开（`grid-auto-rows: auto` + `min-height` 内容下限），列位置保持不动、行位置自然向下顺延，形成类 Pinterest 的瀑布流排布。
- **解决什么问题**：部分组件（日记日历、热力图、数据库看板）在不同数据量下最佳高度不同，固定行跨度要么留白、要么内部滚动；内容自适应可让每个组件始终以"刚好装下内容"的高度呈现，进一步贴近 Apple WidgetKit 的容器智能感。
- **影响哪类用户**：工作台组件数量多（10+）、组件数据量波动大的重度整理用户。
- **预估成本**：**中（2）**（`_05-settings-widgets.scss` 增加可选模式作用域 + `second-panel-ui.ts` 渲染分支 + 拖拽/键盘导航占位计算适配 + E2E 断点回归）。
- **与现有功能是否重叠**：高度重叠。现有架构已提供：自由拉伸把手（拖拽 + Shift+方向键 1~12 列 × 1~10 行）、宽/高步进按钮、尺寸型号菜单与 `grid-auto-flow: dense` 致密自动归位；瀑布流模式会与「拖拽占位网格 + 键盘 Home/End/PageUp/PageDown 导航 + E2E 横向溢出门禁」的行跨度约定产生冲突，需要整条交互链适配。
- **评判结论（2026-11-02）**：**建议不采纳立即实施，保留候选**。理由：① 现有 12 列 + dense 流已是"受约束的瀑布流"，自由拉伸已覆盖"按需调整大小"的核心诉求；② 内容自适应高度会破坏拖拽占位与键盘导航的可预测性（占位框无法预知目标高度），且与 9 项宿主联动中"布局持久化/多窗同步"的行跨度协议耦合；③ 真正的痛点（个别组件高度不合身）可用现有自由拉伸与「荐」尺寸推荐低成本解决。待用户反馈"手动调整太麻烦"成为高频诉求时，再以独立模式（默认关闭）立项。
- **用户审查决策状态**：`待用户审查`
